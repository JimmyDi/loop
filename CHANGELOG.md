# Changelog

Notable changes across Agent, coding-agent, and Web UI are recorded here. Pending changes accumulate under Unreleased; release preparation groups them by version and date. See [Contributing](CONTRIBUTING.md#changelog) for the maintenance workflow.

## [Unreleased]

### Breaking Changes

- coding-agent: approval requests now wait indefinitely by default. ApprovalRequest.expiresAt and DEFAULT_APPROVAL_TIMEOUT_MS may be null; consumers must handle an absent deadline, or pass timeoutMs: 120_000 explicitly to retain the previous SDK timeout. See [approval compatibility](src/coding-agent/docs/approvals.md#compatibility).

- coding-agent and Web: managed sessions and standalone mutating tools now default to read-only instead of unrestricted host access. Restricted Bash requires macOS Seatbelt or Linux Bubblewrap, blocks networking and filters inherited environment variables; unavailable sandbox backends fail closed. Managed session headers upgrade to version 2, which older Loop readers reject. Existing sessions without a preset migrate to read-only. Select workspace-write explicitly to allow workspace mutations, or danger-full-access only when unrestricted execution is intended; see [permissions and migration](src/coding-agent/docs/permissions.md).

### Added

- coding-agent: add session-owned approval requests with unique IDs, pending snapshots, allow-once/reject decisions, cancellation, indefinite waiting by default, optional explicit SDK timeouts, and paired approval events. Require an explicitly registered host interaction handler; missing or failing handlers, invalid/stale responses, and never policy cannot authorize requests. Cancel outstanding requests on abort, run completion or disposal, and never persist pending decisions or grants. Bind managed tool approvals to the actual call ID, validated arguments and operation scope. Allow one exact file replacement with path/content/identity rechecks, or one explicitly requested unsandboxed Bash invocation with host filesystem, network and environment access, while preserving the session preset. Protected storage remains denied to file approvals. Denial, timeout and cancellation prevent dispatch; queued file operations can cancel while another call awaits approval, and failed commands never automatically rerun with broader authority. Expose ApprovalOperation snapshots for review. Web and interactive CLI provide allow-once/reject controls showing exact arguments, reason and file or host-shell scope without an expiry countdown. Web approval summaries use Allow this operation with ${mode} permissions: ${justification}, with a localized prefix, the original model explanation and expandable operation details. Built-in file approvals expose optional permissionMode display metadata derived from the canonical target: workspace-write inside the workspace, danger-full-access outside; unsandboxed shell calls show danger-full-access. Labels do not change the exact-operation grant or session preset, and older requests without a tier retain generic copy. Write/edit accept an optional brief justification, falling back to the policy reason; explanations cannot grant authority and require no extra model call. Web approval cards use an orange rounded border, a tinted Waiting for approval header and right-aligned Deny/Allow once buttons; Allow once has a black background and white text. Web decision endpoints use local request checks; interactive connections share one handler per session, preserve existing pending requests across disconnects and session switches until a decision, cancellation or shutdown, and refresh after stale or uncertain responses without retrying execution. Print and piped input remain noninteractive. See [approval APIs](src/coding-agent/docs/approvals.md).

- coding-agent: persist read-only, workspace-write and danger-full-access presets per managed session, expose idle-only SDK switching and permission_changed events, and support a new-session settings default. Constrain built-in writes with canonical path checks and atomic replacement, protect Loop storage, and sandbox Bash and descendants with private per-call temporary storage. Keep the system prompt stable by projecting durable runtime-context snapshots into model requests only on initial use or policy changes; restore their original positions without affecting displayed conversation history, titles or timing indices. Expose RuntimeContextSnapshot and SessionManager.getRuntimeContexts(), with optional context metadata in commit(). Built-in single-call approval requires an explicitly registered host handler; without one, additional authority is denied. Web adds an idle-only permission menu beside the attachment button below the input, with descriptions, a selected-state checkmark and an orange full-access indicator. Full access requires a separate confirmation dialog describing file, command and network scope; cancellation leaves the saved preset unchanged. Settings → General adds a server-persisted Permission default for new Web sessions across all projects, with matching shield icons, per-level descriptions, a selected checkmark, orange Full access styling and Full access confirmation; existing sessions and CLI/SDK defaults remain unchanged. CLI adds --permission-preset and /permissions, preserving saved presets on resume and leaving new-session defaults independent.

Use the design in the sidebar, welcome screen, assistant avatars, browser favicons and Safari icons. In-app icons switch between the primary charcoal tile with a white-to-blue mark in Light and a white tile with a charcoal-to-blue mark in Dark; System follows the browser preference while explicit selections take precedence. Reserve the icon artwork and application copies under a separate brand asset policy, excluding them from the software's MIT license; retain SIL OFL 1.1 licensing and attribution for the open-source guide fonts. Consolidate icon studies into the final asset package.

- Web UI: dismiss composer and session error notices, including run cancellation, with a close button while preserving drafts, attachments, validation, session outcomes and save recovery. New errors appear again, and dismissal does not carry over to another session.
- Web UI: show a rotating ring at the right edge of session-list rows during response generation, then a blue unread dot for completed output that has not been viewed. While awaiting approval, show a yellow dot to the left of the session title and a static clock icon in place of the right-hand spinner, taking priority over generation and unread indicators and remaining visible across session switches.
