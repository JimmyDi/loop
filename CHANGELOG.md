# Changelog

Notable changes across Agent, coding-agent, and Web UI are recorded here. Pending changes accumulate under Unreleased at the top, followed by releases in reverse chronological order; release preparation groups pending entries by version and date. See [Contributing](CONTRIBUTING.md#changelog) for the maintenance workflow.

## [Unreleased]

### Breaking Changes

- coding-agent: persist sessions in version-3 directories containing meta.json, messages.jsonl and index.json. Explicitly opening a valid legacy session migrates it and retains its original JSONL backup; listing alone does not migrate. Older Loop versions cannot read new history. Session file accessors now identify meta.json; use SessionManager for reads and the collection accessor for session creation. See [session storage](packages/coding-agent/src/docs/session-format.md).

ApprovalRequest.expiresAt and DEFAULT_APPROVAL_TIMEOUT_MS may be null; consumers must handle an absent deadline, or pass timeoutMs: 120_000 explicitly to set a bounded SDK wait. - coding-agent and Web: managed sessions and standalone mutating tools now default to read-only instead of unrestricted host access. Restricted Bash requires macOS Seatbelt or Linux Bubblewrap, blocks networking and filters inherited environment variables; unavailable sandbox backends fail closed. Session headers use version 2 with required permission metadata; other versions are rejected without rewriting data. Select workspace-write explicitly to allow workspace mutations, or danger-full-access only when unrestricted execution is intended; see [permissions](packages/coding-agent/src/docs/permissions.md).
