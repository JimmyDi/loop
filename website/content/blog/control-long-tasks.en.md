While automation keeps working, people still need to understand what is happening and change direction. Clear controls matter more than extra status indicators.

## Distinguish steering from the next task

“Make this change work on mobile too” supplements current work. “Update the documentation afterward” describes later work. The interface should explain when input takes effect rather than make people guess whether a message has been consumed.

## Keep stopping easy to find

Stop should remain available and clearly end current execution. Completed results should remain visible, while unfinished actions should not appear successful. Feedback must follow actual execution state.

## Continue from the results

Before continuing, people should be able to inspect existing results and remaining work. Recovery does not mean replaying every action. It means choosing the next action from the current facts.

A useful long-task experience lets people answer three questions at any moment: what is happening, when will my input take effect, and where can I continue after stopping?
